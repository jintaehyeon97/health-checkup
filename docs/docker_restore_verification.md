# Docker 복원 검증 기록

> **한 줄 요약**
> 백업해 둔 건강검진 데이터베이스를 다른 환경(Docker)에서 다시 열어 보고, **원본과 똑같은지** 확인했습니다.
>
> **쉽게 말하면**
> - **백업과 복원:** 데이터를 통째로 복사해 두는 것이 백업이고, 그 복사본으로 되돌려 놓는 것이 복원입니다.
> - **Docker:** 프로그램을 컴퓨터 환경과 상관없이 똑같이 실행하게 해 주는 상자입니다. 어느 컴퓨터에서든 같은 환경을 만들 수 있습니다.
> - **확인 방법:** 데이터 건수(100만 건), 특정 조건으로 조회한 결과(23,884건), 전체 내용을 하나의 숫자로 요약한 값(체크섬)이 원본과 같은지 비교했습니다. 모두 같았습니다.
> - **의미:** 컴퓨터가 고장 나도 백업으로 같은 데이터를 다시 만들 수 있고, 다른 사람도 같은 환경에서 결과를 다시 확인할 수 있습니다.

- 검증일: 2026-10-19
- 목적: 원본(Windows PC의 SQL Server Express)에서 만든 백업을 Docker 컨테이너의 SQL Server에 복원했을 때 같은 데이터·같은 쿼리 결과가 재현되는지 확인

## 환경
| 구분 | 원본 | 복원 환경 |
|---|---|---|
| 실행 | Windows PC, SQL Server 2025 Express | Docker 컨테이너 `mcr.microsoft.com/mssql/server:2025-latest` (Express) |
| 접속 | Windows 인증 (`localhost\SQLEXPRESS`) | SQL Server 인증 `sa` (`localhost,14330`) |
| DB 이름 | `healthdb` | `healthdb_restore` (별도 이름으로 복원) |

## 복원 절차
1. `RESTORE FILELISTONLY` 로 논리 이름 확인: `healthdb`(데이터), `healthdb_log`(로그)
2. `RESTORE VERIFYONLY ... WITH CHECKSUM` 으로 백업 파일 검사
3. `RESTORE DATABASE healthdb_restore ... WITH MOVE` 로 컨테이너 경로에 복원

## 검증 결과
| 검증 | 원본 `healthdb` | 복원본 `healthdb_restore` | 결과 |
|---|---|---|---|
| `fact_checkup` 행 수 | 1,000,000 | 1,000,000 | 일치 |
| 쿼리 A (`sido_code = 11 AND (sbp >= 140 OR dbp >= 90)`) `cnt` | 23,884 | 23,884 | 일치 |
| 내용 체크섬 `CHECKSUM_AGG(BINARY_CHECKSUM(*))` | -1831381524 | -1831381524 | 일치 |
| 인덱스 | - | `pk_fact_checkup`, `ix_checkup_sido_bp`, `ix_checkup_year_age_sex` | 복원 확인 |
| `etl_log` | 읽음 1,000,000 = 적재 1,000,000 + 제외 0 (OK) | 1건 확인 | - |

## 데이터 품질 점검 (원본에서 실행)
허용 범위는 `sql/05_quality_checks.sql`의 직접 설정한 예시 기준이며, 의학적 정상 범위가 아닙니다.

| 항목 | 기준 | 건수 |
|---|---|---|
| 같은 연도·가입자 중복 | 2건 이상 | 0 |
| 이완기혈압 | 30~200 밖 | 3 |
| 공복혈당 | 20~800 밖 | 7 (20 미만 4, 800 초과 3) |
| 허리둘레 | 40~200 밖 | 12 (999.0 5, 40 미만 6, 200 이상 1) |
| 이완기혈압 > 수축기혈압 | - | 0 |

값은 삭제·수정하지 않고 건수만 기록했습니다. 허리둘레 999.0은 결측 코드일 수 있으나 데이터 설명서로 확인하지 않았습니다.

## 한계와 미실시 항목
- 성능(조회 시간, 논리적 읽기)은 컨테이너에서 다시 측정하지 않았습니다.
- 복원본에 대한 `DBCC CHECKDB` 무결성 검사는 실행하지 않았습니다.
- 데이터 품질 점검은 원본에서만 실행했습니다.
- 단일 PC, 개발용 `sa` 계정을 사용했으며 로그 백업·시점 복구는 다루지 않았습니다.

## 용어 설명
| 용어 | 쉬운 뜻 |
|---|---|
| 데이터베이스(DB) | 많은 데이터를 표 형태로 모아 두고 빠르게 찾는 저장 공간 |
| 백업 / 복원 | 데이터를 통째로 복사해 두는 것 / 복사본으로 되돌려 놓는 것 |
| Docker, 컨테이너 | 프로그램을 어느 컴퓨터에서나 똑같이 실행하게 해 주는 독립된 실행 공간 |
| 인덱스 | 책의 색인처럼 원하는 데이터를 빨리 찾게 해 주는 목록 |
| 체크섬 | 데이터 전체를 하나의 숫자로 요약한 값. 한 글자라도 다르면 값이 달라져서 "같은 데이터인지" 확인하는 데 씀 |
| `healthdb_restore` | 원본을 건드리지 않으려고 새 이름으로 복원한 복사본 |
| `sa` 계정 | SQL Server 관리자 계정. 이번에는 개발·검증용으로만 사용 |
